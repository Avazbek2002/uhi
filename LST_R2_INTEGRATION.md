# LST Raster Integration: Cloudflare R2 → Frontend

This document explains how Land Surface Temperature (LST) raster imagery flows from the Landsat processing pipeline into the frontend Heat Atlas visualization.

## Pipeline Architecture

### 1. Backend Upload (Python script → R2)

The backend script performs these steps for each Landsat scene:

1. **Download** raw GeoTIFF from Google Earth Engine
2. **Clip** to Tashkent city boundary
3. **Render** a visualization PNG with thermal color ramp
   - Non-data pixels → alpha = 0 (transparent)
   - Valid LST pixels → color-mapped & opaque
4. **Upload** both `.tif` (full data) and `.png` (visualization) to R2:
   - Path pattern: `landsat-lst-scenes/tashkent_YYYY-MM-DD.{png,tif}`
   - Uses `boto3.s3_client.upload_file()` configured for R2 endpoint
5. **Generate manifest** (`maps_manifest.json`):
   - JSON array with `{ date, url, label }` entries
   - Uploaded to: `landsat-lst-scenes/maps_manifest.json`

**R2 Configuration Requirements:**
- Bucket must have **public read access** enabled
- **CORS** must allow `GET` requests from your frontend domain
- Public endpoint: `https://pub-{YOUR_BUCKET_ID}.r2.dev`

### 2. Frontend Retrieval (React + Mapbox)

**Environment Variables** (`.env.local`):
```bash
# Primary manifest URL (generated by upload script)
VITE_LST_MANIFEST_URL=https://pub-ec33c8a1d13f40f4935fa09d39bb00ce.r2.dev/landsat-lst-scenes/maps_manifest.json

# Fallback local manifest for development
# → /public/data/lst-manifest.json
```

**Data Flow:**

1. **Fetch Manifest** on app load:
   - Try `VITE_LST_MANIFEST_URL` first
   - Fallback to `/data/lst-manifest.json`
   - Parse JSON → extract `maps: [{ date, url }]` array

2. **Calendar UI**:
   - Shows available dates with indicator dots
   - User selects a date → updates `selectedDate` state

3. **Raster Display** (`MapboxMap` component):
   ```typescript
   // Selected date → URL lookup
   const selectedLstMap = lstMaps.find(map => map.date === selectedDate);
   
   // Mapbox image source
   map.addSource('lst-raster', {
     type: 'image',
     url: selectedLstMap.url,  // R2 PNG
     coordinates: LST_RASTER_BOUNDS  // Tashkent bbox
   });
   ```

4. **Load Verification**:
   - Pre-flight `new Image()` check with `crossOrigin: "anonymous"`
   - On success → add raster layer to map
   - On error → display CORS/access error message

### 3. Coordinate Bounds

The hardcoded `LST_RASTER_BOUNDS` in `App.tsx`:
```typescript
const LST_RASTER_BOUNDS: RasterBounds = [
  [69.08, 41.42],  // top-left
  [69.45, 41.42],  // top-right
  [69.45, 41.2],   // bottom-right
  [69.08, 41.2]    // bottom-left
];
```
**Must match** the bounding box used by the backend clipping operation.

## Manifest Format

**R2 Location:** `landsat-lst-scenes/maps_manifest.json`

```json
{
  "maps": [
    {
      "date": "2024-06-04",
      "url": "https://pub-ec33c8a1d13f40f4935fa09d39bb00ce.r2.dev/landsat-lst-scenes/tashkent_2024-06-04.png",
      "label": "Landsat acquisition"
    }
  ]
}
```

**Schema:**
- `date` (string): ISO date `YYYY-MM-DD`
- `url` (string): Public R2 URL to the visualization PNG
- `label` (string): Optional display name

## Troubleshooting

### ❌ "LST raster not loaded"

**Possible causes:**

1. **CORS not configured** on R2 bucket:
   - Add CORS rule allowing `GET` from your frontend origin
   - Example rule:
     ```json
     {
       "AllowedOrigins": ["https://yourdomain.com", "http://localhost:5173"],
       "AllowedMethods": ["GET"],
       "AllowedHeaders": ["*"]
     }
     ```

2. **Bucket not public**:
   - Enable public access in R2 dashboard
   - Verify direct URL access in browser

3. **URL mismatch**:
   - Check `VITE_LST_MANIFEST_URL` points to correct R2 domain
   - Verify PNG filenames match `tashkent_YYYY-MM-DD.png` pattern

4. **Bounding box mismatch**:
   - PNG may render outside visible map if bbox is incorrect
   - Verify backend clipping bounds match `LST_RASTER_BOUNDS`

### ✅ Verifying Setup

1. **Check manifest is reachable:**
   ```bash
   curl https://pub-ec33c8a1d13f40f4935fa09d39bb00ce.r2.dev/landsat-lst-scenes/maps_manifest.json
   ```

2. **Check PNG is reachable:**
   ```bash
   curl -I https://pub-ec33c8a1d13f40f4935fa09d39bb00ce.r2.dev/landsat-lst-scenes/tashkent_2024-06-04.png
   ```
   Should return `200 OK` with `Content-Type: image/png`

3. **Browser console**:
   - Open Network tab → filter by `r2.dev`
   - Select a date in calendar → should see PNG request
   - Check for CORS errors in console

## Local Development Fallback

For development without R2 access:

1. Place sample PNG in `/public/data/tashkent_lst_sample.png`
2. Update `/public/data/lst-manifest.json`:
   ```json
   {
     "maps": [
       {
         "date": "2024-06-04",
         "url": "/data/tashkent_lst_sample.png"
       }
     ]
   }
   ```
3. Comment out `VITE_LST_MANIFEST_URL` in `.env.local`

The app will fall back to the local manifest automatically.
